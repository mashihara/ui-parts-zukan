## 3行で

- AIに画面を作らせるとき、指示がずれる一番の原因は「部品の名前を知らない」こと

- 人が見る図面とは別に、AIが読む `llms.txt`・JSON・Claude Code／Codex 用のスキルも用意した

https://mashiharalab.dev/ui-parts-zukan/

## 「出てくる窓」には少なくとも4つの名前がある

Claude Code や Cursor に画面を作らせていて、こんな頼み方をしたことはないでしょうか。

> 上の帯をもう少しおしゃれに
> ボタンを押したら出てくる窓、あれをもっと分かりやすく

「上の帯」はヘッダーです。「出てくる窓」はもっと厄介で、

| 出方・中身 | 名前 |
|---|---|
| 中央に出て、後ろを暗くして操作できなくする | モーダル |
| 「本当に削除しますか？」と返事を求める | ダイアログ |
| 画面の横から滑り出る | ドロワー |
| 画面の下からせり上がる | ボトムシート |

のどれを指しているかで、AIが作る物はまったく変わります。AIの力が足りないのではなく、こちらの言葉が足りていません。

## 同じAIに、同じ画面を2通りで頼んでみた

カフェの予約画面を、同じAI（Claude Sonnet）に2通りで頼みました。

- 名前を知らない頼み方：「上に帯があって、今いくつめの手順か分かるようにして。名前と人数と受け取り方（店内・持ち帰り・配達）を入れられて、禁煙席がいいかどうかと、前の日にお知らせするかどうかも選べるようにして。最後に進むボタン」
- 名前を入れた頼み方：「上にヘッダー、その下にステップ表示（入力→確認→完了、今は入力）。名前はテキストフィールド、人数はセレクトボックス、受け取り方はラジオボタン、禁煙席の希望はチェックボックス、前日のお知らせはトグルスイッチ。最後に『予約内容を確認する』のボタン」

画像：docs/images/compare.png（左が名前なし、右が名前あり）

名前なしでは、人数は数字を打ち込む欄、受け取り方は横並びのボタン、禁煙席はスイッチになり、手順の中身も「日時→内容入力→確認」と勝手に決められました。名前で頼むと、そのとおりに出てきます。

## UI部品図鑑でできること

### 1. 図面で名前を引く

見本の画面の部品から引き出し線を引き、「ヘッダー」「パンくずリスト」「ラジオボタン」「トグルスイッチ」と書き込みました。部品53個に加えて、カラム・sticky・グリッド・フレックスボックス・レスポンシブなど「画面の組み方」のことば15個、合わせて68個を載せています。

画像：docs/images/drawing.png

### 2. 意味と「頼み方の例」を読む

名前を押すと、意味・使いどころ・動く見本と、そのままAIに貼れる頼み方の例が出ます。

> 削除ボタンを押したら確認ダイアログを出して。「削除しますか？」と聞き、「キャンセル」と赤い「削除する」を並べて。

画像：docs/images/entry-dialog.png

部品ごとにページがあり（例：`/parts/modal/`）、検索で「モーダルとは」から直接たどり着けるようにしています。

### 3. まぎらわしい名前を1行で見分ける

取り違えやすい組み合わせ23組に、1行の見分け方を付けました。

- **ツールチップとポップオーバー**：乗せるだけで出て読むだけならツールチップ、押して開いて中も押せるならポップオーバー
- **トーストとアラート**：数秒で勝手に消えるのがトースト、読むまで残るのがアラート
- **スティッキーと固定表示**：固定表示は最初から最後まで同じ位置。スティッキーは決めた位置に来るまでは流れ、そこで止まって付いてくる
- **パディングとマージン**：枠の内側の余白がパディング、外側がマージン

画像：docs/images/confusions.png

### 4. 選んだ名前をまとめてAIへ渡す

使いたい部品を選ぶと、名前・意味・頼み方の例をまとめた文になります。Claude・ChatGPT・Codex・Cursor に貼り、作りたい物を一言書き足すだけです。

## AIに直接読ませる

人が名前を調べてから頼むだけでなく、AIのほうにも辞書を持たせられるようにしました。

| 置き場所 | 中身 |
|---|---|
| `/llms.txt` | サイトの説明・全部品の名前・まぎらわしい名前の見分け方 |
| `/api/v1/catalog.json` | 同じ内容の機械向けデータ |
| `/api/v1/parts/<id>.txt` | 部品ごとの説明と頼み方の例 |

選んだ部品はリンクにも残ります。`?pick=modal,toast` の付いたリンクをAIに渡すと、`llms.txt` に書いたお願いに沿って、pick の id を「使いたい部品」として読みます。

Claude Code・Codex にはスキルとして入れられます。

```bash
npx skills add mashihara/ui-parts-zukan
```

入れておくと、「上の帯」「出てくる窓」のようなあいまいな言い方をされたときに、AIが正式な名前に置き換えて確かめてくれます。

## 作り方のメモ

- **Next.js 16（App Router）の静的書き出し**。`llms.txt` と `api/` もビルドで生成し、名前・意味・頼み方の例の正本は1つのファイル（`parts.ts`）にまとめた。図面・部品のページ・`llms.txt`・スキルが同じデータから作られるので、説明がずれない
- **配信は GitHub Pages、ドメインは自分のサイトから中継**。main に push すると GitHub Actions がビルドして公開し、Vercel 上のましはらラボ（Next.js）が rewrites で `/ui-parts-zukan/` に中継している。canonical とサイトマップは絶対URLにした（相対だとサブパスが落ちる）
- **引き出し線の重なりは e2e で検査**。Playwright で全68語の見本を開き、線どうしの重なり・画面からのはみ出し・スマホ幅の吹き出しが切れないかを毎回確かめる。手で見ていると、部品を1つ足すたびにどこかが重なる
- **見本のCSSのリセットは `:where()` で優先度0に**。`.kit button { … }` のようなリセットを書くと、部品側の `font-weight` 指定が負けて見本が全部同じ太さになった
- **スマホでは名前の札を重ねない**。部品の上に札を重ねると「お名前」「人数」など見本の文字が隠れて分かりにくいので、押した部品のそばに吹き出しで答える形にした

## おわりに

「名前を知っていれば、AIに頼める」という考え方は、大滝昇平さんの [Motion Prompt](https://showheyohtaki.github.io/motion-prompt/)（動きの名前のライブラリ）から学びました。動きの名前はそちらで調べられます。

デザインを学んだことがない人ほど、名前を1つ覚えるだけでAIの出す画面が変わります。足りない部品や、現場ではこう呼ぶという名前があれば教えてください。
